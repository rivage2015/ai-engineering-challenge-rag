## 3. 分けて持つ三つの状態

1. **事実の支持**：原文で支持／原文と不一致／確認できない／具体的な事実回答なし。
2. **質問の充足**：回答済み／一部未回答／未回答／判定処理が未完了。
3. **停止・保留の理由**：以下の区分と、その判断根拠。

例えば「料金は確認できません」は、料金への回答は未完了でも、確認した資料の範囲に応じて引き継ぎは適切になり得る。回答の正しさ、回答の充足、人への引き継ぎの適切さを一つのPASSで潰さない。

### 理由の区分案

| 利用者への説明 | そう説明するための根拠 | 次の一手 |
| --- | --- | --- |
| 原文の意味・対応関係を確定できない | 原文と位置、確定できない担当・条件・対象。モデルだけの判断なら「曖昧と断定」せず「対応を確定できない」とする | 該当する原文を示し、具体的な確認を一つ |
| 今回の検索・確認範囲では根拠が見つからない | 確認した資料・版・取得範囲。範囲が不明なら不明と記録 | 検索範囲や別資料の所在の確認。資料に存在しないとは断定しない |
| 読み取りを完了できなかった | 対象資料・版に対応するReaderの失敗記録 | 読めなかった場所と分かる範囲の原因を示す。無関係なファイルの失敗を今回の原因にしない |
| 回答と根拠の対応を点検できなかった | 監査・引用・関係の診断結果 | 点検側の課題として保留。資料の書き直しを求めない |
| 処理上の問題で止まった | 通信・容量・終了状態・JSON検証等の実測記録 | 段階と要求IDを示す。業務上の説明を人に求めない |
| 意図・資料の版が決まらない／原文が食い違う | 既存の意図・版・矛盾の安全判定。同一対象・時点の矛盾なら両方の原文 | 既存の確認導線を使う。別の検索経路で迂回しない |
| 原因をまだ特定できない | 未回答であることだけ確認でき、上記の根拠が不足 | 「原因未特定」と明示。もっともらしい理由を生成しない |

複数原因は併記できる。主に進行を止めている理由を一つ選び、他を消さない。処理エラーがある場合、そのエラーを資料の欠陥の証拠にしない。単にEvidence IDがある／ないだけで原因を決めない。

## 4. 最小の入出力と表示

既存の `answer_status / answer_mode / covered` を置き換えず、最初は別の診断レコードとして試す。

- 要件ID：確認済みの意図契約の項目。原文が一つでも複数要件へ接続可能だが、それぞれの支持を確認する。
- 回答の状態：実質的に回答済みか。回答済みなら最終表示文の正確な抜粋。
- 理由区分と確定度：実測で確認できたこと／原文に基づく判断候補／原因未特定。
- 診断根拠：原文ID・引用・位置、または処理イベントIDと段階。処理ログを業務内容のEvidenceにしない。
- 確認した範囲：資料・版・検索範囲・読取未完了・省略の有無。記録がなければ不明。
- 必要な情報と次の担当：利用者による意味・資料・版の確認か、アプリ側の処理確認か。
- 再検討条件：何が変われば再検討できるか。単なる再試行で解消すると保証しない。
- 確認質問：人の回答で前に進める場合だけ、回答全体で最大一つ（要件ごとに一つではない）。正常回答や技術エラーへ業務上の質問を機械的に付けない。

全要件を一度ずつ記録し、未回答ID一覧はこの一覧から機械的に導く。ID欠落・重複・型不正を、資料不足へ変換しない。引用の文字一致だけでは意味の支持を証明できないため、意味の対応は別に評価する。

表示は「確認できた内容 → 未確認の項目 → 理由 → 確認用原文と場所 → 次の一手」。内部の詳細診断は折りたたむ。日本語の短い説明にし、正しい担当・条件まで誤りだと指摘しない。

原文は正式な出典読取経路だけから取得する。モデルが返したファイルパスを直接開かない。除外資料・未承認版・索引世代の不一致・機密除外・引用検査の保護を維持する。読めていないセルやページ番号を推測しない。表示を切った場合は省略を明示し、不存在判断に使わない。

人からの補足は原資料とは別の情報として扱う。原文の引用や版を上書きしない。今回は新しい会話保存・学習・知識書換え機能を作らず、まず確認質問の表示までを対象候補とする。補足の永続保存や再回答への接続は、その保存範囲を定める後続カードで扱う。

## 7. 「95%」の前に、別々に測るもの

- **答えられる問題での正答率**：根拠が足りる問題を分母にし、回答内容・範囲・条件が正しいかを見る。
- **不要な保留率**：同じ分母で、答えられたはずなのに保留した件数を見る。
- **答えられない問題での適切な保留率**：根拠不足・曖昧さの固定問題について、創作せず理由と必要な確認を示せたかを見る。
- **根拠のない回答率**：答えられない問題を答えた、または支持のない主張を混ぜた件数を別表示する。
- **理由の正確さ**：分類・不足項目・原文との対応・指摘箇所が正しいか。合否が合っていても説明が違えば理由評価は失敗。
- **処理未完了率・所要時間・確認回数**：技術失敗を正当な保留の成功件数に加えない。総件数と、除外せず残した失敗件数も示す。

平均一つにまとめず、各件数と分母を併記する。一般精度95%は、今回の小さな固定セットでは認定しない。別の未知問題による評価が必要。
