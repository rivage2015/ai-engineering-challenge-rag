# APIキー不要のローカル意味検索 v0.1

## 目的

BM25で拾いにくい言い換えを、ローカルの埋め込みモデルで補う。
外部APIキーは使わず、意味検索の結果もSearchUnitとEvidenceへ追跡できるようにする。

## 構成

- 実行基盤: ローカルOllama
- モデル: `embeddinggemma` 621 MB、768次元
- 文書プロンプト: `title: none | text: {text}`
- 検索プロンプト: `task: search result | query: {query}`
- 類似度: L2正規化後のコサイン類似度
- 統合: BM25と意味検索の順位をweighted RRFで統合

意味索引にはモデル名だけでなくdigestを保存し、検索時に導入済みモデルと
一致するか確認する。行列、メタデータJSONL、元SearchUnitのSHA-256も状態に記録する。
代表51件は同一モデル・同一入力で2回構築し、埋め込み行列、メタデータ、
状態JSONがバイト単位で一致した。

## 適応型ハイブリッド

意味検索を常に強く混ぜると、日付や表番号など語彙一致が強い問いの順位を
下げる場合があった。そのため通常の意味重みは0.25とし、次の両方を満たすときだけ
1.0へ引き上げる。

1. BM25の1位候補が一致した質問トークンの比率が0.25未満。
2. BM25の1位スコアを2位スコアで割った値が1.4未満。

この判定は質問の内容、案件名、ファイル名、正解IDに依存しない。

## 評価

人手確認済みの通常16問では、BM25+構造再ランキングのHit@1 1.0、
MRR 1.0、Recall@10 1.0をそのまま維持した。

同じ確認済み原本位置に対し、固有語と原文の語彙を減らした言い換えストレス8問では、
次の変化となった。この8問は通常性能の推定ではなく、語彙が欠けた場合の比較用である。

| 指標 | 語彙+構造 | 適応型ハイブリッド |
|---|---:|---:|
| Hit@1 / Recall@1 | 0.125 | 0.25 |
| Hit@5 / Recall@5 | 0.125 | 0.50 |
| Hit@10 / Recall@10 | 0.50 | 0.625 |
| MRR | 0.174 | 0.328 |

## 境界

- Ollamaと`embeddinggemma`の事前導入が必要。
- `--base-url`をローカル以外へ変更すると、指定先へ検索本文が送信されるため注意する。
- 埋め込み行列の読み書きとコサイン計算にNumPyが必要。
- ローカルモデルであっても意味上の誤召回は起こるため、Evidence確認は省略しない。
- 現時点の検証索引は代表4形式の51 SearchUnit。大規模索引は別途検証する。
