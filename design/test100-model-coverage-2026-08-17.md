# 100問モデルカバレッジ計画（2026-08-17）

## 結論

100問を質問本文と資料インベントリだけから分類すると、主なボトルネックはOCR単体ではない。最大の群は「複数資料・版・時点・案件横断」30問で、次が「Office書式・配置・コメント・ページ」20問である。加えて、47問は何らかの決定的な計算・集計を必要とする。

現時点で内部的に `machine_certified` と数えられるのは15問、残る85問は `unproven` である。ただし、これは正解データとの一致数ではない。`machine_certified` は、出典から回答までを機械的に追跡・再計算・検証できる状態を表す。`unproven` には、回答は生成されたが証明経路が不足するもの、棄却したもの、必要エンジンをまだ統合していないものが含まれる。

各モデルのEnd-to-End列は、100問の回答経路へ統合して同一条件で実行するまで、すべて `not_tested` とする。OCR領域PoCや単一資料での成功を、問題を解けた証明として流用しない。

## 調査範囲と禁止事項

本分類で読んだものは次の2種類だけである。

- `share/質問回答/questions_test.csv` の100件の質問本文
- `share/共有ドライブ` 配下のファイル名、拡張子、フォルダ構造からなる資料インベントリ

正解、検証用回答、既存予測、既存回答本文は読んでいない。特に `questions_valid.csv`、投稿ZIP内の予測、回答ログを分類根拠に使用していない。そのため、本資料は「どの問題が正解だったか」を示す表ではなく、「各問題を解くために何が必要か」を先に閉じる能力分類である。

資料インベントリは419ファイルで、主要形式は `.py` 100、`.png` 54、`.docx` 46、`.md` 31、`.csv` 29、`.pdf` 28、`.json` 28、`.pptx` 26、`.xlsx` 21、`.ipynb` 11、`.tsv` 2である。画像化する前のネイティブ構造が多く残っているため、追加OCRより先にネイティブ抽出を使う余地が大きい。

## 0.40000から問題別の正誤を復元できない理由

第4回投稿の `0.40000` は集約された評価値であり、問題ごとの判定結果を含まない。仮に評価指標が問題単位の平均であっても、同じ0.4を作る正誤の組合せは多数存在する。次の情報は集約値だけからは判定できない。

- どの質問IDが正解または不正解だったか
- 正解が抽出、検索、計算、意味判断、回答形式のどの段階によるものか
- 異なるモデルが同じ問題で同じ根拠を読めたか
- 回答を生成したが未検証なのか、根拠不足で棄却したのか
- 偶然正解した回答と、再現可能な証拠経路を持つ回答の区別

したがって、0.4を40問の確定正解へ機械的に割り当ててはならない。比較対象は当面「正誤」ではなく、問題ごとの証拠充足状態とEnd-to-End実行状態にする。

## 証明ベースの比較方法

各質問について、モデル名ごとに直接回答を保存するのではなく、まず次を記録する。

1. 必要資料が一意に解決できたか。
2. 必要なテキスト、表セル、書式、座標、グラフ値、コード設定を取得できたか。
3. 値と出典ページ・セル・オブジェクト・コード位置を対応付けられたか。
4. 比較、フィルター、集計、計算を決定的に再実行できたか。
5. 列挙漏れ、単位、丸め、期間、ID種別、版の向きを検証できたか。
6. 最終回答が上記証拠だけから生成されたか。

問題別状態は次のように分ける。

| 状態 | 意味 |
|---|---|
| `machine_certified` | 資料解決、根拠取得、変換、計算、出力検証がすべて通る |
| `answered_unverified` | 回答は出たが、必要根拠または再計算可能性が不足する |
| `abstained` | 不足を検出し、推測せず回答を棄却した |
| `not_tested` | 対象モデル・エンジンをEnd-to-End経路へ未統合 |

`answered_unverified` と `abstained` を「不正解」とは呼ばない。一方で、100問をすべて解ける状態の証明にも使わない。正解データを見ない段階では、`machine_certified` の拡大を進捗指標にする。

## 次に追加する技術・モデルの優先順位

最優先は新しい生成モデルの追加ではなく、ネイティブ構造と決定的実行を閉じることである。

1. **Native Office・表計算・コード抽出**：raw OOXML、`openpyxl`、`python-docx`、`python-pptx`、`pandas`、`nbformat`、Python ASTを組み合わせる。外観依存17問、計算依存47問、コード依存6問へ最も広く効く。
2. **型付き計算器と資料横断グラフ**：数値、通貨、率、時間、日付区間、ID、人物、案件、版、状態遷移を型付きで処理する。これはモデルではなく、モデル出力を検証する基盤である。
3. **グラフ専用Chart-to-Tableモデル**：ネイティブデータやNotebookから再構成できない7問の残差だけを対象に、DePlot、UniChart、ChartOCR、ChartVLM系を比較候補にする。導入時に最新版、ライセンス、日本語軸、ローカル実行性を再確認する。
4. **複雑PDFのレイアウト・表分割**：現行Doclingで表が誤統合される残差に、PP-Structure、MinerU、Surya、Marker系を比較する。OCR文字精度ではなく、領域分割・reading order・row/column対応を評価する。
5. **座標接地できるローカルVLM**：Q044とQ058、および画像だけに残る図形関係に、Qwen-VL・InternVL系を候補にする。自由記述ではなく、bbox付きObservationを必須にする。
6. **追加OCR**：上記処理後も「文字そのものが読めない」問題だけに追加する。既存OCRと同じ誤りを増幅するモデルは採用しない。

モデル数は進捗指標にしない。未証明質問を能力別に減らし、15件の `machine_certified` を100件へ近づけることを指標にする。
