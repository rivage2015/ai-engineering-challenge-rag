## Closed invariant and exact scope

At the standalone document-version resolver validation API/CLI, a graph is accepted only when it matches the complete deterministic result reconstructed from explicitly supplied inventory and optional explicitly supplied decision input under the current policy. Bootstrap's existing immediate pre-Reader gate must pass the same caller-configured decision path that its preceding build used. This closes the stored-graph forgery boundary at that invocation only.

This is NOT full F05 or V1 acceptance. Reader selection/Validator/projector do not yet invoke this strict reconstruction after the initial gate. A graph swap after this gate, independent full Reader partition coverage, immutable decision snapshots for old generations, UI review integrity, decision lease/revision, source freshness and whole-system races remain required follow-on work. Do not route a historical generation's revalidation to a mutable shared decision file implicitly. This is a staged previously unimplemented boundary, not a reset of an exhausted repair cycle.

## Trusted inputs, compatibility and fixed semantics

1. Keep `validate(graph_path, inventory_path)` syntactically valid and add optional explicit `decisions_path=None` (keyword accepted) plus CLI `validate --decisions`. Return shape remains `status: PASS|FAIL` with an errors list. CLI success/failure exit code stays 0/1.
2. The validator reads graph, caller-supplied inventory, and a present caller-supplied decision file once each into bytes snapshots; parse and hash those exact bytes. It never calls build/atomic_json/record_decision, writes files, opens original documents, or follows, resolves or stats paths obtained from graph JSON. Snapshot equality is not proof that no concurrent filesystem change ever occurred.
3. No explicit decisions means an empty decision map and no digest. A graph claiming a non-null decision digest cannot pass without explicit matching input. A harmless stored path-only claim with null decision digest is permitted for compatibility with build's missing-file behavior, but supplies no authority. An explicitly supplied missing decision file also means empty/no digest; a graph with a recorded digest then fails. Other read/parse failures are failures, never a fallback to empty. Do not use strict=True resolution of the optional missing path in the CLI.
4. Explicit present decisions must match the graph's recorded digest and be used to reconstruct all effects, including stale choices. Stored source path strings are diagnostic metadata, never input discovery or authority. Require the source container/fields/types, but do not claim filesystem path identity or current source-root attestation from matching data digests.
5. Reconstruct candidate fields and complete family membership from inventory, not from submitted groups. Preserve the current eligibility filter, unchanged family_key, at-least-two plus at-least-one-signal inclusion, byte ordering, candidate-set hash representation, automatic selection, full-set Human selection and stale precedence. Compare all candidate fields including size_bytes, even though the existing set hash excludes size_bytes.
6. Reconstruct every group, node, edge, policy and count from those inputs. Compare complete canonical JSON so boolean/integer coercion cannot pass and missing/extra/reordered/duplicate semantic output is rejected. Source inventory/decision digests, graph self hash, schema/resolver identity and current policy must agree. Generated created_at is checked as a nonempty string, not regenerated as a correctness oracle. Reject missing/extra top-level semantic fields rather than ignoring alternative outputs.
7. Reject malformed JSON/required containers, duplicate JSON object keys (including nested keys), ambiguous duplicate inventory relative paths and duplicate decision group IDs before dictionary collapse. Preserve the current candidate eligibility interpretation for other ineligible records; this is not a full Path inventory schema or arbitrary resource-limit certification. Exceptions from normal invalid JSON/types/file IO become a structured failure; do not hide AssertionError from test guards.
8. Bump resolver identity 0.1.3 to 0.1.4 for the new validation contract. Old-policy graphs are not silently authenticated as current. Existing code-identity registration causes rebuild requirements; do not rewrite old generations. Builder behavior/load_inventory/load_decisions/record_decision remain unchanged except a pure shared deterministic reconstruction/policy refactor if necessary and this identity bump. Their wider snapshot/race/authentication limits remain explicit.
