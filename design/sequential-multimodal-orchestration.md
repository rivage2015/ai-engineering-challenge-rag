# 逐次マルチモーダル画像理解 v0.1

## Step 7 source実装との関係

この文書は完成済み仕様ではなく、逐次マルチモーダル経路の最終設計である。
Step 7のsource実装で完了したのは次の範囲に限る。

- macOS PDFKit/JXAによるPDFのページ単位ローカル描画、native text取得、既存OCR接続
- 単体画像と、DOCX・XLSX・PPTX・Notebookの参照付き埋め込みラスター画像のOCR接続。Office・Notebookのraw埋め込み画像は表示representation・crop・透過・transformが未解決なので、複数OCR一致時も暫定扱いとし確定グラフから除外する
- XLSX・PPTXのOOXML表示関係とhashに結合したネイティブグラフの保存済みラベル/値cacheの検索化。`verified_ooxml_chart_cache`は出典結合と構造検証の表示であり、Officeでの最新再計算や内容の正しさの保証ではない。DOCXのネイティブグラフ構造は未対応
- PPTX SmartArtの参照付きテキスト要素と生の`srcId`/`destId`接続。接続typeや配置の意味は推定しない
- `gemma4:12b`による質問非依存の文字通りの視覚観測。常に`[暫定読取]`とし、確定回答と確定意味グラフの単独根拠に使わない

一方、Agent 1/2の独立実行とAgent 3による融合、Office全ページ/全スライド/
全シートのレンダリング、タイル分割、高解像度再試行、色・配置からの
意味融合は未実装である。非対応、cache欠落、SmartArt端点不解決、
OCR/VLMの不足、または安全上限到達は`partial`または`unresolved`とし、
完了に昇格しない。実行時の読取りはMac内とloopback Ollamaだけで完結し、
原本と画像を外部APIへ送信しない。

## 目的

テキスト抽出だけでは失われる画像、グラフ、表計算の表示状態、
色、マーカー、配置、階層を、ローカルOllamaの`gemma4:12b`で質問非依存に
抽出する。

処理時間より正確性を優先し、モデル呼び出しは並列化せず1件ずつ逐次実行する。
同じ原本画像は質問ごとに再解析せず、入力ハッシュ、モデルdigest、プロンプトversionで
キャッシュする。

## 適用範囲

画像理解の対象は次のいずれかに該当するものとする。

- PNG、JPEGなどの画像ファイル
- テキスト層を持たないPDFページ
- PDF、PPTX、DOCXの埋め込み画像
- グラフ、マーカー、色、図形配置が意味を持つページまたはスライド
- PivotTable、フィルター表示、結合セル、複数行見出しなど、
  表示上の構造が意味を持つシート領域

次は画像理解ではなく構造抽出を正とする。

- CSV・TSVの全行集計
- XLSXの非表示セル、数式、原値、厳密な数値
- IDや小数の完全一致
- 画像の範囲外にある行の存在確認

## 構成

### Orchestrator

プログラムによる状態管理層とする。LLMに実行順序や再試行回数を
自由判断させない。

- 対象の発見と優先度付け
- 画像のレンダリングと分割
- Agent 1、2、3の逐次実行
- JSON Schema検証
- 構造データとの照合
- 再試行と終端状態の決定
- 中間結果のキャッシュ

### Agent 1: transcription

文字、数値、表の行列候補を忠実に転記する。意味解釈、誤字修正、
補完を禁止する。

必須出力:

- 転記文字列
- 文字またはセル候補の領域
- 読み取れない箇所
- 複数候補がある場合の候補列

### Agent 2: visual-state

文字の忠実な転記ではなく、表示状態と視覚的関係を観測する。
Agent 1の出力は渡さず、観測の独立性を保つ。

必須出力:

- 色、マーカー、太字、下線などの強調
- セル、行、列、ブロックの配置
- 結合、階層、グループ、親子の候補
- グラフの軸、凡例、系列、点の対応候補
- 空白に見える領域。欠損とは断定しない

### Agent 3: fusion

次の3入力を統合し、意味構造を生成する。

1. 原本からの機械的な構造抽出
2. Agent 1の転記結果
3. Agent 2の視覚状態結果

出力する関係の例:

- 列名と値
- フィルター列と条件
- PivotTableのフィルター、行階層、集計項目、集計値
- マーカーと対象文字列
- グラフの軸値、系列、最大・最小候補

根拠を伴わない解釈は出力しない。入力間の矛盾は仲裁せず
`conflicts`へ残す。

### Verifier

可能な範囲を決定的なプログラムで照合する。

- 原本セル値と転記数値の一致
- 列名と列番号の対応
- セル範囲と画像タイルの対応
- 同一領域への矛盾した値の割り当て
- 出力Schemaとprovenanceの完全性

## 逐次ワークフロー

```text
discover
  -> discover_chart_source
      -> recover_chart_table
      -> validate_chart_table
          -> verified_source_table -> build_search_units
          -> source_unavailable
  -> native_extract
  -> render
  -> transcribe
  -> analyze_visual_state
  -> fuse
  -> verify
      -> verified
      -> retry_high_resolution
      -> unresolved
  -> build_visual_evidence
  -> build_search_units
```

グラフは画像解析より先に、同じプロジェクト内の生成コードと
元データを探す。対応する生成式が安全に再構成できる場合は、
厳密値を持つ `ChartTable` を正とする。生成元がない、式を安全に
認識できない、または表示状態そのものが問題になる場合に限り、
後段の逐次マルチモーダル解析を行う。

### ChartTable

- x軸値、系列名、系列ごとの全ポイントを保持する。
- 複数y軸は系列と軸の対応を明示する。
- 値ごとに `exact / estimated / unresolved` を保持する。
- コード、データ、画像のパスとSHA-256を記録する。
- 検出系列数と出力系列数、各系列の点数を決定的に検査する。

1つの画像に対するモデル呼び出しは常に逐次とする。Agent 1が完了し、
結果が安全に保存された後にAgent 2を実行する。Agent 2にAgent 1の結果は
与えない。Agent 3だけが両結果を受け取る。

## 画像レンダリング

- PDFはページ単位で高解像度にレンダリングする。
- PPTXとDOCXはページまたはスライド全体と、表・グラフの拡大領域を分ける。
- XLSXは使用範囲を表領域ごとに分割する。タイルには行・列見出しを繰り返し含める。
- PivotTableはレポートフィルター、行ラベル、値フィールドを1枚に収める。
- グラフは全体画像と軸・凡例・データラベルの拡大画像を作る。
- 色の異なる複数系列は、軸を薄く残しつつ一系列ずつ強調した分離画像を作る。
- 全体図、系列別図の順で観測し、全体図で数えた系列を省略しない。

## 再試行

再試行は最大2回とする。

1. 初回は標準画像で全工程を実行する。
2. 矛盾または読み取り不能領域があれば、対象だけを高解像度で切り出す。
3. 数値だけが不明な場合は、数値領域と対応見出しに限定して再解析する。
4. 2回後も解消しなければ`unresolved`とし、推測値を保存しない。

## キャッシュと再開

画像ごとに次を保存する。

- 原本ファイルと画像のSHA-256
- 原本位置、ページ、スライド、シート、セル範囲
- 使用モデル名とdigest
- プロンプト名とversion
- Agentごとの生出結果
- 経過時間、再試行回数、最終状態

同じハッシュ、モデルdigest、プロンプトversionの工程は再実行しない。

## 信頼度

モデルが自己申告する確信度をそのまま使わない。次の観測から
パイプライン側で決める。

- 構造抽出と画像転記の一致率
- Agent 1とAgent 2の領域対応の一致
- 再試行前後の結果の一致
- Schema、参照、数値整合性検証の結果

## 質問非依存性

- 大会の質問文、record ID、正解は画像解析へ渡さない。
- ファイル形式、画像内容、原本構造だけで処理を決める。
- 生成結果は回答ではなく、再利用可能なEvidenceとRelationにする。

## 初回検証

正解付き30問の診断で前処理不足とした画像・表示構造系の
代表対象を使う。正解文字列は生成プロンプトに渡さず、生成後のみ照合する。

1. マーカー付き最終報告ページ
2. `figure_06.png`のグラフ
3. 複数階層を持つPivotTable
4. AutoFilterが適用されたXLSXシート

比較項目:

- 現行テキスト抽出で保持できた事実
- Agentごとの観測結果
- 統合後に追加できた事実
- 原本表示との一致
- 誤転記、誤対応、根拠のない推論の件数
- 1画像ごとの実行時間と再試行回数

## 実装順序

1. 中間出力Schemaとキャッシュ状態を定義する。
2. Ollamaの画像入力クライアントと単一画像の再開可能な実行器を作る。
3. Agent 1とAgent 2の独立プロンプトを実装する。
4. Agent 3とVerifierを実装する。
5. 画像、PDF、PPTX/DOCX、XLSXの順にレンダラーを接続する。
6. 代表4対象を1件ずつ実行し、原本と比較する。
7. 効果が確認できた形式だけを全件処理へ広げる。
