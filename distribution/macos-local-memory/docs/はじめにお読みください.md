# Local Memory Search 導入ガイド

## 目的

「あの頃どうしたっけ」「あの人と何を話したっけ」のような曖昧な記憶から、自分のMac内の資料を探し、根拠付きで答えるローカル検索システムです。

## 相手の方が行う操作

1. DMGを開き、`Local Memory Search.app`を「アプリケーション」へ移動します。
2. 初回だけ、Controlキーを押しながらアプリをクリックし、「開く」を選びます。
3. macOSがフォルダやファイルへのアクセス許可を求めたら、許可します。
4. 検索したいフォルダを1つ選びます。必要なら、その上位フォルダを選びます。
5. 画面の「初回セットアップを開始」を押します。初回はモデル取得のため時間がかかります。
6. 準備完了後、ブラウザの入力欄に普通の言葉で質問します。

GitHubやターミナルの知識は不要です。

## 必要なMacの状態

| 項目 | 最低 | 推奨 |
|---|---:|---:|
| macOS | 14 Sonoma | 14以降の最新更新版 |
| チップ | Apple Silicon M1以降 | M2以降 |
| メモリ | 16GB | 24GB以上 |
| 空き容量 | 25GB + 検索対象 | 40GB以上 + 検索対象 |
| インターネット | 初回の導入・モデル取得時のみ | 同左 |

- Intel MacでもOllamaはCPU実行できますが、12Bモデルは非常に遅くなります。この試作パッケージはApple Siliconを実用対象とします。
- Python 3.10以降がない場合、許可後にPython Software Foundationの署名を検査した公式インストーラを自動取得して開きます。インストーラはクリックで完了し、その後アプリを再度開きます。
- Ollamaがない場合、許可後に公式DMGを自動取得します。コード署名とTeam IDを検査してから、そのユーザーのApplicationsへ自動導入します。

初回に取得するモデルの実測容量は、回答用 `qwen3.5:9b` が約6.6GB、監査用 `gemma4:12b` が約7.6GB、検索用 `embeddinggemma` が約621MBです。Ollamaの更新で容量が変わる場合があります。

## 取り扱う形式

- 本文を索引化: TXT、Markdown、CSV、JSON、YAML、HTML、DOCX、PPTX、XLSX、テキスト抽出可能なPDF
- 名前とメタデータのみ: 画像、音声、動画、圧縮ファイル
- 対象外: 古い `.doc` / `.xls` / `.ppt`、暗号化ファイル、画像だけのPDF、手書きOCR

PDFはMacのSpotlightから本文を取れない場合、`pdftotext`が必要です。パッケージ内の診断ログに未抽出ファイルが残ります。

## プライバシー

- 通常利用中の質問、検索対象、回答、索引は、そのMacの中で処理します。
- AIの通信先は `127.0.0.1:11434` のOllamaに限定します。Web UIも `127.0.0.1:8765` にだけ公開します。
- 初回のOllama導入とモデル取得は外部通信を使います。
- プロンプトインジェクションの可能性がある資料は、質問と無関係な事前ゲートで分離し、通常回答の索引から除外します。
- 初段の回答とは別のローカルモデルが最終監査し、核心の根拠が不足する場合は「わかりません」に停止します。

## 保存場所と初期化

設定、索引、キャッシュ、ログは以下に保存されます。

`~/Library/Application Support/LocalMemorySearch`

アプリは原本ファイルを変更しません。初期化する場合は、このフォルダをゴミ箱へ移し、アプリを再起動します。

## 未署名試作版の注意

このDMGはAppleの開発者証明書で署名・公証していない試作版です。はじめに配布者からSHA-256値を受け取り、DMGが改変されていないことを確認してください。
