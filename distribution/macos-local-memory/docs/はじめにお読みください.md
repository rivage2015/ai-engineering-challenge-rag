# Local Memory Search 導入ガイド

## 目的

「あの頃どうしたっけ」「あの人と何を話したっけ」のような曖昧な記憶から、自分のMac内の資料を探し、根拠付きで答えるローカル検索システムです。

このDMG／ZIPは2026-09-05時点のLocal visual Reader／OCR scheduling v0.6です。Answer promotion v0.5を含み、app bundleの表示版は`0.6`、build番号は`6`です。

## 相手の方が行う操作

1. DMGを開き、`Local Memory Search.app`を「アプリケーション」へ移動します。
2. 初回だけ、Controlキーを押しながらアプリをクリックし、「開く」を選びます。
3. macOSがフォルダやファイルへのアクセス許可を求めたら、許可します。
4. 検索したいフォルダを1つ選びます。必要なら、その上位フォルダを選びます。
5. 画面の「初回セットアップを開始」を押します。初回はモデル取得のため時間がかかります。
6. 準備完了後、ブラウザの入力欄に普通の言葉で質問します。

GitHubやターミナルの知識は不要です。

## 必要なMacの状態

| 項目 | 最低 | 推奨 |
|---|---:|---:|
| macOS | 14 Sonoma | 14以降の最新更新版 |
| チップ | Apple Silicon M1以降 | M2以降 |
| メモリ | 16GB | 24GB以上 |
| 空き容量 | 25GB + 検索対象 | 40GB以上 + 検索対象 |
| インターネット | 初回の導入・モデル取得時のみ | 同左 |

- Intel MacでもOllamaはCPU実行できますが、12Bモデルは非常に遅くなります。この試作パッケージはApple Siliconを実用対象とします。
- Python 3.10以降がない場合、許可後にPython Software Foundationの署名を検査した公式インストーラを自動取得して開きます。インストーラはクリックで完了し、その後アプリを再度開きます。
- Ollamaがない場合、許可後に公式DMGを自動取得します。コード署名とTeam IDを検査してから、そのユーザーのApplicationsへ自動導入します。
- HomebrewのCLI版Ollamaだけが入っている場合も利用できます。daemonが停止していれば、`127.0.0.1:11434`に限定して起動し、`logs/ollama-serve.log`に記録します。

初回に取得するモデルの実測容量は、回答と別コンテキストの監査で共用する `gemma4:12b` が約7.6GB、検索用 `embeddinggemma` が約621MBです。Ollamaの更新で容量が変わる場合があります。

## 取り扱う形式

- 本文を索引化: TXT、Markdown、CSV、TSV、JSON、XML、YAML、コード、Jupyter Notebook
- 構造付きで索引化: DOCXの本文・見出し・表、XLSXのシート・セル・数式・結合範囲、PPTXのスライド・本文・表・対応図表・明示SmartArt。追加ライブラリがないMacでも標準ライブラリReaderを使います。
- ローカルOCR: PNG、JPEG、TIFF、BMP。Apple Visionを主とし、Tesseractがある場合は別方式と比較します。文字と位置が独立した2方式で一致した行だけを高信頼とします。
- PDF: ネイティブ文字をページ単位で保持するとともに、各ページをMac内でPNGに描画し、スキャンPDFや画像だけのPDFもローカルOCRの対象にします。ページ描画器またはOCRが使えない場合は、読めたと扱わず制限付きで残します。
- 埋め込み画像: PDF内の画像はページ上に見える状態で、DOCX、XLSX、PPTX、Jupyter Notebookの対応画像は画像単位で、それぞれローカル読取の対象にします。画像単位で対応するのはPNG、JPEG、TIFF、BMPです。
- DOCX、PPTX、PDFは、完全ローカルのReaderとmacOS標準機能の範囲で読み取ります。高度な書式、変更履歴、レイアウト継承、グループ変換などを解決できない場合は、完全に読めたと表示せず、制限付き完了と理由を残します。
- 本文の読取対象外: 音声、動画、圧縮ファイル、古い `.doc` / `.xls` / `.ppt`、暗号化ファイル。SVG、GIF、WebP、EMF、WMFなどの非対応画像は、埋め込みの存在を残しても画像内容までは読み取りません。

画像OCRの単独観測や同じengine内だけの一致は、`[暫定読取]`として位置付きで索引に残します。位置付きOCRが1行も読めない画像は、導入済みの`gemma4:12b`で画像全体を再読し、座標なしの忠実な文字起こしを同じ暫定層に残します。AIを読取に使ったかどうかはLayer 1のEvidence provenanceから自動判定し、検証します。

Office・Notebookの埋め込み画像は、表示時の画像選択、切り抜き、透過、変形をまだ完全再現できません。そのため、複数OCRが一致しても埋め込み画像の文字は`[暫定読取]`のままとし、確定グラフには上げません。

図・表・写真については、`gemma4:12b`が質問と無関係に、見える対象、明示ラベル、矢印や凡例などで明示された関係、図表に文字で明記されたラベル付きの値だけを観測します。棒の高さや軸目盛から数値を推定せず、判読できない値は数値を補完せず不明とします。顔からの個人同定や、外見からのセンシティブ属性の推測も行いません。

このGemmaによる意味観測も、必ず`[暫定読取]`として検索用にだけ保持します。それだけで確定回答を作らず、確定グラフの根拠にもしません。手書き、極端な低解像度、小さなラベル、回転や反射、複雑な表のセル対応、ラベルのないグラフ数値の精度は保証対象外です。

上のPDF描画、OCR、Gemmaによる意味観測は完全ローカルで実行し、読取対象のファイルや画像を外部へ送信しません。初回のアプリ導入とモデル取得だけは、前述のとおり外部通信を使います。

初回セットアップでは、まずモデルなしのReader結果と安全性を検証します。その後、画面の「初回セットアップを開始」で許可された範囲内でモデルを取得し、Gemmaが新たに使えるようになった場合だけ画像を含む読取工程を自動で再実行し、再検証後の結果を公開します。

この試作版のApple Vision helperは初回にMac上でコンパイルするため、Xcode Command Line Toolsの`xcrun`/`swiftc`が必要です。それがない場合は、既に導入済みのTesseract 5.5.2と日本語・英語辞書を使います。どちらも使えない場合、画像は読み取れたと表示せず、制限付きで残します。

## プライバシー

- 通常利用中の質問、検索対象、回答、索引は、そのMacの中で処理します。
- AIの通信先は `127.0.0.1:11434` のOllamaに限定します。Web UIも `127.0.0.1:8765` にだけ公開します。
- `127.0.0.1`への通信はMacのHTTP proxy設定を使わず直接接続します。Web UIはHost検査と起動ごとの秘密tokenを使い、外部Webページからの操作を拒否します。
- 初回のOllama導入とモデル取得は外部通信を使います。
- プロンプトインジェクションの可能性がある資料は、質問と無関係な事前ゲートで分離し、通常回答の索引から除外します。
- 回答と同じローカルモデルを、回答文脈から分けた監査役としても実行します。その前に決定論的な主張・Evidence検証を行い、核心の根拠が不足する場合は「わかりません」に停止します。

## 保存場所と初期化

設定、索引、回答ログは以下に保存されます。

`~/Library/Application Support/LocalMemorySearch`

初回導入用のPython／Ollamaインストーラcacheは、別に次へ保存されます。

`~/Library/Caches/LocalMemorySearch`

アプリは原本ファイルを変更しません。索引と設定を初期化する場合は、Application Support側のフォルダをゴミ箱へ移し、アプリを再起動します。この操作ではinstaller cache、導入済みPython、Ollama本体・モデル、login Keychain項目は削除されません。

Answer promotion v0.5は、意味グラフの改ざん検出用に非秘密のhashを世代ごとにmacOS login Keychainへ保存します。Keychain項目の削除機能はまだないため、上のApplication Supportフォルダを削除してもこのhashは残ります。

索引作成中にMacが再起動したりプロセスが強制終了した場合は、次回起動時にbuild leaseと世代recordを照合し、途中の未公開世代だけを整理して画面に「再実行」を表示します。公開まで完了していた世代は削除せず、準備完了状態へ復旧します。

アプリを続けて二度開いた場合も起動処理は1本ずつ実行します。Python未導入時の初回起動も、macOSのカーネルが管理するロックで1本に限定します。強制終了や電源断でもOSがロックを自動解放するため、次回起動を古いPIDが永続的に妨げません。別のターミナル処理が索引を作成中なら復旧確認を待ち、終了後に残った途中状態を確認してから画面を利用可能にします。120秒間継続して稼働状態を確定できない場合は、誤って準備完了とせず起動失敗に停止します。
